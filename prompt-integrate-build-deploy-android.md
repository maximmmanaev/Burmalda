# Завести арт в игру, собрать APK и задеплоить на подключённый Android — на ревью Max'у

## Предпосылка

Ассеты уже должны лежать в `Assets/Art/...` (см. `prompt-commit-push-scenario-assets.md`
— скачивание и коммит в ветку `feat/scenario-art-assets-batch1`). Если этой
ветки/файлов ещё нет — сначала выполни ту задачу, потом эту. Если есть —
работай поверх неё (не обязательно создавать новую ветку, можно продолжить
в той же).

Сгенерировано и реально лежит в репозитории (проверь перед началом,
`ls Assets/Art`):
```
Assets/Art/Tiles/            — 14 файлов (8 базовых плит + 6 ловушек/ворот)
Assets/Art/Icons/Currencies/ — 4 файла
Assets/Art/Icons/Artifacts/  — 5 файлов (только 5 названных в ArtifactCatalog,
                                не 15 — остальные ещё не придуманы дизайном)
Assets/Art/Cards/Omens/      — 6 файлов
Assets/Art/AppIcon/          — 1 файл (app-icon.png)
```
Категорий `Boss/` и `Backgrounds/` в этом пакете НЕТ — Комната Босса ещё не
реализована в Unity (PRD v8), фоны сознательно не генерировались. Не
пытайся их найти или придумать заглушки.

## Задача

### Шаг 1 — импорт в Unity

1. Настрой Texture Import Settings:
   - `Tiles/` — Texture Type под то, как будешь накладывать на меш (см.
     шаг 2) — Default или Sprite, на твоё усмотрение.
   - `Icons/Currencies/`, `Icons/Artifacts/`, `Cards/Omens/`, `AppIcon/`
     — обязательно "Sprite (2D and UI)", Alpha Is Transparency = true.
2. Не трогай Compression агрессивно на этом проходе — дефолт ок.

### Шаг 2 — тайлы тоннеля

`TunnelDebugVisual` сейчас красит примитив через
`ApplyColor(tileObject, TileDebugColor.Resolve(state))` — однотонный
материал. Замени на назначение текстуры: `Renderer.material.mainTexture`
(или спрайт, если решишь перейти на Quad — см. ниже про UV) по
`TileVisualState`, та же логика веток, что сейчас в `TileDebugColor.Resolve`,
просто вместо `Color` — текстура/спрайт из `Assets/Art/Tiles/`.
Если решишь сохранить debug-цветной режим как fallback-флаг — на твоё
усмотрение, опиши решение в отчёте.

Если текстуры на боковых/верхних гранях `Cube` выглядят растянуто/криво —
переход на `Quad` для верхней грани допустим, опиши это решение отдельно,
не тихой правкой.

### Шаг 3 — иконки валют и артефактов

1. Подставь спрайты валют туда, где сейчас HUD уже выводит числа
   (`CurrencyController` + существующий UI поверх него). Не создавай новый
   экран, если его ещё нет — просто подготовь Image-слот рядом с текстом.
2. Артефакты — если UI инвентаря/Ритуала уже отображает артефакты по Id
   (`ArtifactCatalog`), подставь спрайт по маппингу filename → Id. Если
   такого UI ещё нет — не строй его с нуля, зафиксируй в отчёте, что
   спрайты готовы и ждут экрана.

### Шаг 4 — карты Знамений

Аналогично шагу 3: подставляй в `OmenSelectionSystem`, если экран выбора
уже существует. Не строй его заново, если нет.

### Шаг 5 — иконка приложения

`Player Settings → Icon` → `app-icon.png`, размеры Unity сгенерирует сам
из одного квадратного PNG.

### Шаг 6 — прогон тестов

Unity Test Runner на чистой пересборке. Логика (`TunnelGrid`/
`GridTraceTrail`/`Tile`/`TileVisualState`) не должна была пострадать —
если хоть один тест упал, значит задета не та зона, откатывайся и
разбирайся, не игнорируй красный тест.

### Шаг 7 — сборка Android-билда и деплой на подключённое устройство

1. Убедись, что Android выбран как активная платформа
   (`Build Settings → Android → Switch Platform`, если ещё не переключено).
2. Проверь, что устройство реально видно:
   ```
   adb devices
   ```
   Если пусто/`unauthorized` — сообщи мне, не пытайся чинить USB-debugging
   настройки на телефоне сам, это должен разрешить я на устройстве.
3. Собери и установи билд одним из двух путей — выбери сам, какой у тебя
   быстрее настроен:
   - Unity `Build And Run` (сам соберёт, задеплоит и запустит на
     подключённом устройстве), либо
   - Собери `.apk` в `Builds/Android/` вручную, затем:
     ```
     adb install -r Builds/Android/<имя>.apk
     adb shell am start -n <package.name>/<полное.имя.Activity>
     ```
     (package name смотри в Player Settings → Other Settings →
     Package Name).
4. После запуска подожди 5–10 секунд и сними лог на предмет ошибок
   текстур/null reference:
   ```
   adb logcat -d | grep -iE "error|exception|null" | tail -n 50
   ```
5. Сделай скриншот с устройства для отчёта:
   ```
   adb exec-out screencap -p > screenshot-android-art.png
   ```
   Сохрани его в корень репозитория (или пришли мне отдельно, если так
   удобнее) — мне нужно увидеть, как выглядят новые тайлы/иконки на
   реальном экране, не только в редакторе.

## Отчёт

Пришли мне: скриншот с устройства, package name/версию билда, что из
шагов 3–4 реально удалось подставить (а что осталось «спрайт готов, экрана
нет»), лог ошибок (если есть), статус тестов (все зелёные / что упало).

## Важно — не коммить и не пушить пока

Как и с камерой раньше в этой ветке: жду твой отчёт и скриншот, сам
проверю билд на телефоне и дам добро. Только после моего OK — коммить
изменения интеграции (`TunnelDebugVisual` и что ещё тронешь) отдельным
коммитом от коммита с самими ассетами, conventional commit style, без
самоатрибуции агента (см. `docs/rules/git-workflow.md`), и пушить.
