# Дисциплина правок и расход контекста

Источник — внешний обзор репозиториев/практик для Claude Code (2026-09):
thedotmack/claude-mem, affaan-m/everything-claude-code, obra/superpowers,
shanraisshan/claude-code-best-practice, forrestchang/andrej-karpathy-skills,
плюс раздел про расход токенов (CLAUDE.md-гигиена, точные промпты,
`/clear` между атомарными сессиями, prompt caching). Ниже — что из этого
реально применимо к работе агента в ЭТОМ репозитории, не пересказ статьи
целиком. Что не внедрено и почему — см. последний раздел.

## Дисциплина правок (адаптировано из andrej-karpathy-skills)

Уже частично покрыто [implementation-workflow.md](implementation-workflow.md)
(архитектура → тест → код) — здесь усиление на уровне каждой отдельной
правки, не задачи целиком:

- **Думать прежде, чем писать код.** Явно проговаривать (себе и в чате)
  предположение, на котором строится правка, прежде чем её делать — не
  писать код "на пробу", надеясь, что предположение подтвердится по ходу.
- **Минимально жизнеспособное решение.** Никаких спекулятивных функций
  "на будущее", если их не просили — это то же самое, что уже запрещает
  [forbidden-actions.md](forbidden-actions.md) для баланса/контента,
  распространено на код вообще.
- **Хирургические изменения.** Не трогать код, которого задача не
  касается. Если получилось 200 строк там, где по факту хватило бы 50 —
  переписать компактнее до коммита, а не оставлять как есть. Не расширять
  область правки "раз уж всё равно открыл файл".
- **Явный критерий успеха.** Перед тем как считать задачу сделанной —
  сформулировать, что именно является доказательством (конкретный
  зелёный тест, конкретное поведение на устройстве), и проверять именно
  это, а не полагаться на "выглядит нормально".

## Экономия контекста (адаптировано из раздела статьи про токены)

Раздутый контекст = раздутый счёт и более медленная/менее точная работа.
Применимо к тому, как агент сам читает/исследует репозиторий:

- **Читать точечно, а не файлом целиком**, если известно, какая часть
  файла нужна (`offset`/`limit` у `Read`, а не весь файл "на всякий
  случай") — особенно для больших файлов вроде `SegmentTemplateCatalog.cs`
  или `docs/wiki/changelog.md`.
- **Не перечитывать то, что уже прочитано в этой же сессии** — если файл
  уже был прочитан и с тех пор не менялся, полагаться на то, что уже
  есть в контексте, а не читать заново "для верности".
- **Не расширять зону исследования шире, чем требует задача.** Явно
  заданный scope (конкретный класс/файл/issue) — не повод сканировать
  весь репозиторий "чтобы понять контекст лучше", если задача этого не
  требует. Расследование шире заданного скоупа — оправдано только когда
  что-то в заявленной посылке задачи не сходится с кодом (см. ниже) — и
  тогда это явно проговаривается, а не делается молча.
- **CLAUDE.md/docs/rules — точные и короткие**, без общего контекста,
  который не нужен для конкретной правки. Текущий `CLAUDE.md` (10 строк,
  ссылка на индекс правил) уже соответствует этому — не раздувать его
  добавлением деталей, которые логичнее живут в `docs/rules/<тема>.md`
  или `docs/wiki/`.
- Раздельные атомарные сессии (`/clear` между несвязанными задачами) и
  prompt caching — решения владельца/пользователя на уровне того, как
  запускается CLI и собственные интеграции с API, не то, что агент
  меняет в файлах репозитория.

## Что не внедрено в этот репозиторий и почему

- **ultraworkers/claw-code — НЕ используется и не будет.** Это слитая
  кодовая база самого Claude Code, запускаемая локально в обход
  официальных ограничений Anthropic. Соотношение 108 000 форков на
  184 000 звёзд — аномалия (у здоровых репозиториев форков в 10–15 раз
  меньше, чем звёзд, отмечено в самой статье), плюс происхождение из
  "слитых источников" — не то, что стоит клонировать, аудировать или
  интегрировать без отдельного явного решения владельца продукта вне
  контекста этой задачи. Не подходит под правило "dual-use требует явной
  авторизации" — здесь речь не о легитимном исследовательском
  инструменте, а о нелегальном/неавторизованном обходе продукта
  Anthropic.
- **claude-mem / superpowers / everything-claude-code — не установлены
  агентом.** Это плагины/конфигурации самого CLI Claude Code (глобальные
  для machine/аккаунта, не файлы этого репозитория) — устанавливаются
  командами вроде `/plugin install superpowers@claude-plugins-official`
  или `npx claude-mem install`, которые запускает пользователь сам, если
  решит. Установка глобального инструмента без явной просьбы — вне
  скоупа "перепиши файлы из rules".
- **Prompt caching пример на Python (`cache_control`) — не относится к
  этому проекту.** Burmalda — Unity/C#-игра, не обёртка над Anthropic
  API; этот приём актуален для тех, кто сам строит интеграцию с API, не
  для правил работы агента в игровом репозитории.
